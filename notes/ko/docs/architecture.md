# 아키텍처와 구현 로드맵

## 목표

사용자가 선택한 하나의 Vault에서 노트 검색, 읽기, 편집을 제공합니다.
파일 접근과 MCP 전송 계층은 분리합니다.

## 연결 아키텍처

Vault은 클라이언트에 종속되지 않는 stdio 및 Streamable HTTP MCP 인터페이스를 제공합니다. 로컬 MCP 클라이언트는 직접 연결할 수 있고, ChatGPT는 아래의 선택적 터널 연결을 사용합니다.

개인 개발: ChatGPT → Secure MCP Tunnel → 로컬 MCP 서버 → Vault.
현재 stdio 서버는 로컬 클라이언트와 터널 연결의 기반을 제공하며 ChatGPT에 자동 등록되지는 않습니다. 터널 연결에는 Platform 터널 설정, 런타임 키, 적절한 권한, ChatGPT 개발자 모드 접근 권한이 필요합니다.

공개 배포: ChatGPT → 공개 HTTPS MCP 게이트웨이 → 인증된 로컬 에이전트 → Vault.
이 제안 아키텍처에는 사용자·기기·Vault 매핑, OAuth, 오프라인 처리, Streamable HTTP 지원이 필요합니다. Secure MCP Tunnel은 플러그인 공개 배포에 필요한 공개 엔드포인트를 대체하지 않습니다.

HTTP 모드: MCP 클라이언트 → 인증된 `/mcp` → 세션별 MCP 서버 → Vault.
정확히 일치하는 Host/Origin 허용 목록과 공유 Bearer 토큰을 사용하며 기본적으로 루프백에 바인딩합니다. 지침 검토 상태는 세션별로 분리됩니다. HTTP는 단일 소유자용이며, 공개 다중 사용자 인증에는 여전히 게이트웨이가 필요합니다.

## 구현 로드맵

1. 구현 완료: Vault 상대 경로 검사, 숨김 파일·제외 경로 필터링, 심볼릭 링크·하드 링크 거부.
2. 구현 완료: 결과 제한과 SHA-256 리비전을 제공하는 `search_notes`, `read_note`.
3. 구현 완료: `create_note`, `patch_note`, 미리보기 검증, 리비전 검사, 원자적 생성·교체, 숨김 백업. MCP 쓰기에는 세션 내부에서 대상 경로에 연결된 지침 검토 토큰이 필요합니다. 지침이 불완전하거나 변경되면 작업을 차단합니다.
4. 구현 완료: 파일 트리, 범위별 지침 검색, 허용 목록 기반 설정 조회. 워크플로 스킬은 향후 작업입니다.
5. 구현 완료: 로컬 터널 초기화, 진단, 포그라운드 실행 스크립트. 계정 설정과 ChatGPT 전체 연결 검증은 사용자가 수행해야 합니다. [연결 가이드](chatgpt-connection.md)를 참고하세요.
6. 공개 HTTPS 게이트웨이, 인증, 심사용 테스트 Vault, 제출 자료.

## 구현 원칙

- 절대 경로는 로컬 설정에만 두고 도구 입력은 Vault 상대 경로로 제한합니다.
- 스킬 지침에만 의존하지 않고 서버 코드에서 접근 권한을 강제합니다.
- 범용 셸 또는 임의 코드 실행 도구를 노출하지 않습니다.
- 노트 내용은 데이터로 취급합니다. 노트 안의 지침이 접근 권한을 바꾸면 안 됩니다.
- 작업에 필요한 검색 결과와 노트 내용만 반환합니다. 로컬 저장이라고 해서 데이터가 기기를 떠나지 않는 것은 아닙니다.

파일 도구는 Node.js 파일시스템 API로 저장된 Markdown과 허용된 설정 파일을 읽습니다. 범용 명령 또는 JavaScript 실행 도구는 노출하지 않습니다. 파일 접근 정책은 임시 Vault로 테스트합니다. 이는 애플리케이션 수준의 검사이며, 악의적인 동시 디렉터리 교체를 막는 OS 샌드박스는 아닙니다. 노트 쓰기는 리비전 검사, 원자적 교체, 로컬 백업을 사용합니다. 외부 편집기와의 경합은 도구 가이드에 설명합니다.

## 에이전트 인터페이스

각 도구의 설명과 스키마에는 목적, 경로 의미, 결과, 제한, 부수 효과를 명시합니다. 조회·설정 도구는 읽기 전용이며 생성·편집 도구에는 쓰기 어노테이션이 있습니다. `vault://docs/tools`는 도구 가이드를 제공합니다. 지침 적용 범위와 설정 파일 이름은 프로젝트 규칙입니다.
