# 프로젝트 작업 방식

- 프로젝트의 기본 문서는 영어로 작성합니다. 사용자 요청에 따라 각 원본 Markdown 경로를 그대로 반영한 한국어 번역을 `notes/ko` 아래에 유지합니다.
- 작업은 검토 가능한 크기의 독립적인 변경 단위로 완료합니다.
- 각 변경에 맞는 검사를 실행하고 해당 작업을 커밋한 뒤 다음 작업을 시작합니다.
- 변경 내용을 설명하는 간결한 커밋 메시지를 사용합니다.
- `.env`, 인증 정보, 개인 Vault 내용, 의존성, 빌드 결과물은 커밋하지 않습니다.
- 사용자가 요청하지 않으면 커밋을 푸시하지 않습니다.
- Obsidian 특화 도구 설명은 공식 문서를 근거로 작성하고 관련 출처를 연결합니다.
- 각 도구의 목적, 경로 규칙, 출력, 제한, 부수 효과를 문서화합니다. 프로젝트 규칙과 Obsidian 자체 동작을 구분합니다.
- 동작을 변경할 때 `docs/tools.md`와 MCP 도구 메타데이터를 일치시킵니다.
